# Accessibility standard

**Open Pen Protocol is built accessible by design. WCAG 2.2 Level AA is the bar for every
user-facing surface, enforced in CI.** Automated checks are necessary but not
sufficient: we never claim conformance from them alone, and we say plainly what
has been verified with a screen reader and what hasn't.

## 1. Surfaces

| Surface | Platform layer | Automated check |
|---|---|---|
| Settings app (`crates/opp-settings`, GTK4 + libadwaita) | AT-SPI2 | AT-SPI2 tree test (names, roles, focus order), required before the crate lands (`tools/a11y/check.sh`) |
| `oppctl` command line | terminal | output readable without colour; `--no-color` respected; no information in colour only |
| Desktop notifications from `oppd` | freedesktop notifications | text carries the full message; no icon-only states |
| Pen haptics | the pen | every haptic cue has a visual or audible equivalent; haptics can be turned off |

## 2. Hard rules

1. No information conveyed by colour alone (battery, pairing and connection state pair colour with text).
2. Full keyboard operation of every feature, with a visible focus indicator.
3. Every interactive element has an accessible name and role in the AT-SPI2 tree.
4. Text contrast ≥ 4.5:1 (large text and UI components ≥ 3:1) in light **and** dark themes.
5. Layouts survive 200 % text scale without loss of content or function.
6. Respect the desktop's reduce-motion setting; no flashing content.
7. Pointer targets at least 24×24 px.
8. Haptic previews in settings always show a visual (and optional audible) equivalent.

## 3. Reports

Accessibility issues are triaged against a named WCAG 2.2 success criterion and
treated as release-blocking bugs.
